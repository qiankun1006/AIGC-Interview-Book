## 一、基础概念

1. Redis 是什么？与 Memcached 相比有哪些优势和劣势？  -- Memcached多少年前被淘汰的
2. Redis 为什么是单线程的？单线程为什么还能这么快？ -- 内存操作。没有上下文切换和中断成本，没有锁。高效数据结构，不会有长期阻塞的操作（渐进式哈希）。多路IO复用。
3. Redis 6.0 引入了多线程，多线程用在哪里？命令执行还是单线程吗？ -- 内存数据的读写操作还是单线程，Redis 6.0 的多线程仅用于“网络 I/O 的读写和协议解析”
4. Redis 的应用场景有哪些？分别举例说明。 
5. Redis 的数据存储在内存中，服务器重启后数据会丢失吗？如何保证持久化？
6. Redis 的操作都是原子性吗？ -- Redis 的原子性并非依赖于锁，而是依赖于顺序执行
7. Lua 脚本 和 事务对比？

## 二、基础数据结构

### String
6. String 的底层编码有哪几种？分别在什么场景下使用？ -- 三种，int指针直接存数据，embstrRedisObject 和 SDS 紧挨在一起，一次内存分配搞定，raw的分界点（44字节），有升级但是不可逆
7. SDS（简单动态字符串）相比 C 字符串有哪些优化？ -- len（已使用）、alloc（总内存）、flags（标识类型）
   预分配 + 惰性释放 减少内存重分配次数，O(1)获取长度， 杜绝缓冲区溢出，二进制安全。说白了就是空间换性能和安全。
   +------------+------------+--------+----------------+----------------+--------+
   |  len (1B)  | alloc (1B) | flags  |     buf ...    |    free ...    |  \0    |
   |   (5)      |   (8)      |  (1)   |    "Hello"     |     (2B)       | (1B)   |
   +------------+------------+--------+----------------+----------------+--------+
8. `INCR` / `INCRBY` 的原子性是如何保证的？ --单线程，另外int型直接计算，超出int 则类型判断。对于业务场景，将 GET、INCR、SET组合在一个 Lua 脚本中。
9. String 最大能存储多大的值？ -- 512MB，大Key不推荐

20. ZSet 的底层数据结构是什么？ziplist 和 skiplist 的切换条件是什么？  -- 元素数量 < 128 && 所有member长度<64字节
21. 跳表的原理是什么？为什么 Redis 不用红黑树实现 ZSet？ -- 红黑树对 范围、排名topN 的支持不行，而且其实也不省空间
