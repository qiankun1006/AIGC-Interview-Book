# 二维 DP 状态转移不对称总结

> 这里的"不对称"指：**同一个 dp[i][j]，在不同条件下，转移来源的数量、方向、计算方式都不一样。**
> 和循环顺序不对称不同，这里聚焦的是 if/else 分支里的转移逻辑。

---

## 不对称的本质原因分类

### 类型一：字符相等 vs 不等，来源数量不同

> 相等时多一个"对齐消耗"的来源，不等时只能"跳过"

典型题：**115、1143（LCS）**

### 类型二：特殊字符导致某列/某格有完全不同的逻辑

> 某个字符（如 `*`）打破了"每步消耗一个"的规律，引入跳步或0消耗

典型题：**10（正则 `*`）、44（通配 `*`）**

### 类型三：操作不对称，某个方向额外加1，另一个不加

> 两维度代表不同操作，不同操作的代价不同

典型题：**72（编辑距离，相等不加1，不等加1）**

---

## 题目详解

---

### LeetCode 115 — 不同的子序列

**dp[i][j]：** s 的前 i 个字符中，t 的前 j 个字符作为子序列出现的次数

```
s[i-1] == t[j-1]：
    dp[i][j] = dp[i-1][j]        ← 跳过 s[i]，不用它匹配
             + dp[i-1][j-1]      ← 用 s[i] 匹配 t[j]，两者同时消耗

s[i-1] != t[j-1]：
    dp[i][j] = dp[i-1][j]        ← 只能跳过 s[i]
```

**不对称点：**
- 相等时有 **2 个来源**（选择用/不用），是"加法"，方案数累计
- 不等时只有 **1 个来源**（必须跳过），j 不动，只有 i 消耗

**理解口诀：** `s` 是"供给方"，可以随时跳过；`t` 是"需求方"，只有被匹配时才消耗。

---

### LeetCode 10 — 正则表达式匹配

**dp[i][j]：** s 的前 i 个字符能否被 p 的前 j 个字符匹配

```
p[j] == '*'：
    dp[i][j] = dp[i][j-2]                                       ← * 匹配 0 次（p[j-1]* 整体消掉）
             || (dp[i-1][j] && (s[i]==p[j-1] || p[j-1]=='.'))   ← * 再匹配一个 s[i]（i消耗，j不动）

p[j] == '.' 或普通字符：
    dp[i][j] = dp[i-1][j-1] && (s[i]==p[j] || p[j]=='.')        ← 普通字符对齐匹配
```

**不对称点：**
- `*` 分支：j 可以跳 2 格（消耗 0 个），或 i 消耗 1 个、j 不动（重复匹配）
- 普通字符分支：i 和 j 同时消耗 1 个
- 两个分支的**依赖坐标完全不同**（`[i][j-2]`、`[i-1][j]` vs `[i-1][j-1]`）

**理解口诀：** `*` 的核心是"0 次消耗"和"重复消耗"两个选择；普通字符只有"对齐消耗"一个选择。

---

### LeetCode 44 — 通配符匹配（与10对比）

**dp[i][j]：** s 的前 i 个字符能否被 p 的前 j 个字符匹配

```
p[j] == '*'：
    dp[i][j] = dp[i][j-1]     ← * 匹配 0 个字符（j 消耗，i 不动）
             || dp[i-1][j]    ← * 匹配 1 个或多个（i 消耗，j 不动）

p[j] == '.' 或普通字符：
    dp[i][j] = dp[i-1][j-1] && (s[i]==p[j] || p[j]=='.')
```

**和 LeetCode 10 的区别（重要！）：**

| | LeetCode 10（正则 `*`） | LeetCode 44（通配 `*`） |
|--|--|--|
| `*` 的含义 | 前一个字符重复 0 或多次 | 匹配任意长度的任意字符 |
| 匹配 0 次 | `dp[i][j-2]`（消掉 `x*` 两格） | `dp[i][j-1]`（消掉 `*` 一格） |
| 匹配多次 | `dp[i-1][j]`（i消耗，j不动，且要求字符相等） | `dp[i-1][j]`（i消耗，j不动，无字符限制） |

---

### LeetCode 72 — 编辑距离

**dp[i][j]：** word1 的前 i 个字符转换为 word2 的前 j 个字符所需最少操作数

```
word1[i-1] == word2[j-1]：
    dp[i][j] = dp[i-1][j-1]                        ← 字符相等，不需要操作，直接继承

word1[i-1] != word2[j-1]：
    dp[i][j] = min(dp[i-1][j-1],                   ← 替换：两者同时消耗，+1
                   dp[i-1][j],                      ← 删除 word1[i]：i 消耗，j 不动，+1
                   dp[i][j-1]) + 1                  ← 插入：j 消耗，i 不动，+1
```

**不对称点：**
- 相等时：**0 个操作**，来源唯一（斜对角线）
- 不等时：**3 个操作**，3 个来源取最小，且每个来源都 +1

**理解口诀：** 相等是"白捡"，不等是"花钱"。花钱的方式有三种，取最便宜的。

---

### LeetCode 1143 — 最长公共子序列（LCS）

**dp[i][j]：** s1 的前 i 个字符和 s2 的前 j 个字符的最长公共子序列长度

```
s1[i-1] == s2[j-1]：
    dp[i][j] = dp[i-1][j-1] + 1    ← 必须选这两个字符，斜对角线 +1

s1[i-1] != s2[j-1]：
    dp[i][j] = max(dp[i-1][j],     ← 跳过 s1[i]
                   dp[i][j-1])     ← 跳过 s2[j]
```

**不对称点：**
- 相等时：来源唯一（斜对角线），且必须 +1，没有选择权
- 不等时：只能跳过其中一个，两个来源取最大，不加 1

**和 115 的对比：**

| | LeetCode 115（子序列计数） | LeetCode 1143（LCS） |
|--|--|--|
| 相等时 | `dp[i-1][j] + dp[i-1][j-1]`（两个来源相加） | `dp[i-1][j-1] + 1`（一个来源，+1）|
| 不等时 | `dp[i-1][j]`（s跳，t不动） | `max(dp[i-1][j], dp[i][j-1])`（各跳一个取最大）|
| 语义 | 计数问题（求和） | 最优化问题（求最大）|

---

## 横向对比总结

| 题目 | 相等分支 | 不等分支 | 不对称核心 |
|-----|---------|---------|----------|
| 115 不同子序列 | `dp[i-1][j] + dp[i-1][j-1]`（2来源加法） | `dp[i-1][j]`（1来源） | 来源数量不同 |
| 1143 LCS | `dp[i-1][j-1] + 1`（1来源+1） | `max(dp[i-1][j], dp[i][j-1])`（2来源取max）| 相等时唯一来源必须选，不等时取优 |
| 72 编辑距离 | `dp[i-1][j-1]`（不加1） | `min(三个方向) + 1`（加1） | 相等不花代价，不等花代价 |
| 10 正则匹配 | `dp[i][j-2]` 或 `dp[i-1][j]`（`*`） | `dp[i-1][j-1]`（普通） | `*` 打破单步消耗，引入0步和j不动 |
| 44 通配符匹配 | `dp[i][j-1]` 或 `dp[i-1][j]`（`*`） | `dp[i-1][j-1]`（普通） | `*` 不绑定前一字符，比10更简洁 |

## 记忆方法

**面试时拿到一道二维DP，快速判断是否有转移不对称：**

```
问自己 3 个问题：

1. 两个字符相等和不等，处理方式一样吗？
   → 不一样就是不对称（115, 1143, 72）

2. 有没有特殊字符（* . ?）打破了"每步各消耗一个"的规律？
   → 有就是不对称（10, 44）

3. 相等时有"选择不消耗"的权利吗？
   → 有就会多一个来源（115相等时：用或不用s[i]）
   → 没有（必须消耗）就只有一个来源（1143相等时：必须选这对字符）
