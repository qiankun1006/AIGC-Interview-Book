场景题

一、缓存相关场景题

设计一个缓存系统（类似 Redis 核心功能）：要求支持 K-V 存储、过期策略、持久化、高可用，需说明数据结构选型（哈希表 / 跳表）、过期键清理策略（惰性删除 + 定期删除）、持久化方式（RDB/AOF）、集群方案（主从 / 哨兵 / 分片）。

如何解决缓存穿透、缓存击穿、缓存雪崩？分别说明现象、根本原因、多种解决方案（需结合场景对比优劣，比如布隆过滤器 vs 空值缓存）。

设计一个本地缓存（如 Guava Cache）：要求支持最大容量、过期时间、淘汰策略（LRU/LFU）、并发安全，需说明核心实现逻辑和线程安全保证方式。

二、存储相关场景题

设计一个分布式文件存储系统（类似 MinIO/OSS）：要求支持文件上传下载、分片上传、容灾备份、权限控制，需说明存储架构（分块 + 索引）、一致性保证、元数据管理方式。

如何设计一个订单存储系统？订单数据具有 “写多读少、需事务、需按用户 / 时间查询” 特点，需说明数据库选型（MySQL / 分库分表）、表结构设计、索引优化、分库分表策略（垂直 / 水平）、历史数据归档方案。

设计一个高并发的消息队列（类似 Kafka）：要求支持高吞吐、低延迟、消息持久化、分区消费、重试机制，需说明架构设计（生产者 /broker/ 消费者）、分区策略、副本机制、消息投递语义（至少一次 / 恰好一次）。

三、高并发系统设计题

设计一个秒杀系统（如电商秒杀）：要求支持高并发请求、防止超卖、接口限流、库存一致性，需说明整体架构（前端 / 网关 / 应用 / 存储）、核心技术点（限流、削峰、分布式锁、库存预扣）、可能的瓶颈及优化方案。

设计一个短链接系统（你举例的场景，补充完整要求）：要求支持长链接转短链接、短链接跳转、访问统计、高可用，需说明编码算法（哈希 / 自增 ID + 进制转换）、冲突解决、缓存策略、跳转重定向方式。

设计一个用户登录系统：要求支持密码登录 / 短信登录、记住密码、单点登录（SSO）、防刷、账号安全，需说明 token 生成策略（JWT/Redis 存储）、短信验证码防刷机制、单点登录实现原理（CAS/OAuth2.0）。

四、分布式系统场景题

设计一个分布式锁：要求支持可重入、阻塞 / 非阻塞、公平 / 非公平、高可用，需对比 Redis/ZooKeeper 实现方案的优劣，说明核心实现逻辑（Redis 的 SETNX+EXPIRE vs ZooKeeper 的临时节点）、异常处理（如锁超时）。

如何实现分布式事务？要求保证数据一致性，需说明 2PC/TCC/SAGA/ 本地消息表 / 事务消息的适用场景、核心流程、优缺点（结合具体业务场景选择，比如电商下单 + 扣库存）。

设计一个分布式限流系统：要求支持全局限流、按接口 / 用户限流、令牌桶 / 漏桶算法，需说明限流规则存储、限流计数方式（Redis 计数器 / 滑动窗口）、集群下的一致性保证。

五、业务系统设计题

设计一个社交平台的 feed 流系统（如朋友圈 / 微博）：要求支持发布动态、关注推送、实时查看、按热度排序，需说明推模式 / 拉模式 / 推拉结合的实现、缓存策略、热点动态优化。

设计一个实时统计系统（如电商 GMV 实时统计 / 直播间在线人数）：要求低延迟、高准确，需说明数据采集方式（埋点 / 日志）、计算引擎选型（Flink/Spark Streaming）、数据存储（Redis/ClickHouse）、峰值处理。

设计一个 API 网关：要求支持路由转发、限流、熔断、鉴权、日志记录，需说明核心模块设计、熔断实现（Sentinel/Hystrix）、鉴权方式（JWT/API Key）、性能优化点。
